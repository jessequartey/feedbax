# Dispatch small processing through Cloudflare Queues

Live production validation measured 20–21 ms CPU after reducing direct cron work, above Workers Free's documented 10 ms allowance. The owner chose to remain on Free and redesign before publishing. Small mode now uses its timer only to enqueue a constant signal; a dedicated queue consumer performs the existing bounded D1/Notion/email/R2 work under Queues' documented consumer limits. A production probe measured 0–1 ms in the timer and 22 ms in a successful consumer. This supersedes ADR-0031's direct execution for small mode; standard mode retains its direct Paid-targeted schedule.

The tradeoff is one additional Free-supported resource, at-least-once delivery, and shared queue quotas. Each Installation uses its own producer/consumer pair, batch/concurrency one, three redeliveries, and a 60-second retry delay. D1 leases, transactional checkpoints, deduplicated events, and provider keys remain authoritative; signals contain no Participant data. Setup, diagnostics, generated configuration, native-runtime checks, and live timer/consumer evidence travel with the change. See the Connected guide for quota calculations and actual-account verification.
