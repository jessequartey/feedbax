# Governance

Feedbax begins with a solo project owner and a public path to shared maintainership.

## Authority

The project owner initially holds final authority over merges, releases, roadmap decisions, trademarks, and the boundary between Core and Feedbax Cloud. Technical decisions affecting Core are documented publicly through specifications and ADRs.

Maintainers may close, defer, split, or decline work that conflicts with the accepted scope. Opening an issue or pull request does not create an obligation to merge it.

## Earning trust

Contributors may earn trusted status through repeated focused contributions, respectful review participation, reliable follow-through, and sound judgment about project scope. Trusted contributors may receive triage privileges; sustained performance may lead to maintainer status and merge authority.

The project will document role changes publicly. Once a second trusted maintainer exists, protected branches require an approval from another maintainer.

## Core and Cloud

Core remains complete and meaningfully self-hostable. Conflicts of interest between Core and the proprietary Cloud offering must be disclosed. Essential existing Core capabilities are not removed merely to create an artificial hosted limitation.
