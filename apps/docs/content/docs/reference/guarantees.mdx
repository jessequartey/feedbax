## Notion-only Profile

- A browser-held Device Profile for continuity on one browser.
- Best-effort duplicate-vote resistance within that profile.
- Public Comments with displayed participant names.
- Server validation and configurable mutation rate limits.

## Notion-only limitations

- Verified human identity.
- Cross-device account continuity.
- One-person-one-vote enforcement.
- Proof that a displayed Comment author is who they claim to be.

## Connected Profile in 0.2.1

The optional [Connected Profile](/docs/guides/connected-profile) adds identity asserted by your existing application, D1-backed unique Votes per application identity, cross-browser Vote state, and verified attribution for new native Notion Comments. Historical anonymous counts and Comments do not become verified. Verified application identity is not legal identity or one-account-per-human enforcement.

Connected 0.2.1 also includes Follows, private Notifications, independent opt-in email and private image attachments. Notion-only Installations retain the limitations above.

## GitHub and ownership in 0.2.2

GitHub changes the Content Provider, not the identity guarantee. Its mandatory D1 database supports private mappings and best-effort unsigned participation; only signed Connected identity establishes continuity across devices. Participants need no GitHub account. Public repository issue content is public immediately, independently of portal publication.

My feedback separates server-verified owner reads from public projections. New signed-in portal submissions gain ownership; old unsigned drafts require both identity and a valid Browser Capability to link. Ownership never permits editing a published or advanced Post. Public HTML and private API caches are separate, and a revoked binding fails closed.

Optional Projects and full lifecycle portability remain follow-up work. Opt-in Observed History and source-only upgrades are included in 0.2.2; their guides state their limits. New Team Member operation tools are deferred. See the [acceptance inventory](https://github.com/jessequartey/feedbax/blob/main/docs/version-0.2.2-acceptance.md) rather than assuming planned capabilities have shipped.
