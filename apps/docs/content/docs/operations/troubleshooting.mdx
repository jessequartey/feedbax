---
title: Troubleshooting
description: Diagnose common Notion, Worker, schema, and Participation failures.
---

## Notion content is missing

Confirm the database is shared with the integration and that the stable property IDs in `src/feedbax.ts` match the expected property types. Run `feedbax doctor`.

## Mutations fail in production

Check Worker secrets, rate-limit bindings, allowed origins, and the deployed Worker's logs. Reproduce first against the Worker preview hostname.

## Votes disappear

The Notion-only Profile stores Participation state in the browser. Clearing browser storage or switching browsers removes that local state. Changing or clearing the Device Profile alone does not grant or remove editing capabilities.

## GitHub pairing or access fails

Use the matching 0.2.2 CLI, verify `/v1/info` on your configured service, confirm the selected repository is installed, and check exact portal/service HTTPS origins. Same-account Worker calls require `global_fetch_strictly_public` or an explicit Service Binding. The service reports a safe pairing phase when setup fails; correct that step and start a new one-use exchange. Do not reuse a consumed callback or paste credentials into a browser.

Run `feedbax doctor` after pairing. Apply every migration, including integration recovery leases and Connected ownership where enabled. A revoked binding must be paired again through both GitHub authorization and portal proof. Repository removal, App suspension and loss of permissions fail closed.

## A GitHub Post is unavailable or cannot be edited

Check the single valid public JSON section and immutable slug, exactly one status label, and independent `feedbax:published` label. Engineering text is deliberately excluded. A retained display status during label conflicts is not edit authority. Draft changes require New/unpublished plus a valid Browser Capability or verified ownership.

## My feedback is empty

My feedback is a Connected feature in 0.2.2 development. Sign in through the configured product application. D1, a Device Profile, matching email or a public Post URL does not establish ownership. Old unsigned drafts need an explicit link while their browser capability and lifecycle remain eligible. Submitted, Supported and Following are independent views; unavailable items do not reveal provider records. Refresh after identity or permission changes.

## A Comment response was lost

The 0.2.2 GitHub portal retains the composer and its tab-held request identity after a failed response. Retry the unchanged message to recover the original Comment, including its existing image associations. A confirmed response clears the intent so a later submission is distinct. Do not create new intents to bypass a pending-reconciliation error; an ambiguous provider write must be checked before another create. Definitive rate limiting retains the same intent and respects the provider retry time.

## Local GitHub content fails after production pairing

Local development uses local D1; the production callback stores directional credentials in remote D1. Applying local migrations creates schema, not authorization. Test the deployed portal or prepare a separate development Installation, origin and repository through the service's trusted-destination setup. Never copy production binding credentials to another Installation.
